# 閱讀邏輯文件生成 Skill

## 使用者輸入模板

使用此 Skill 時，請上傳 BCG 分析簡報 PPTX 並提供以下資訊：

```
請根據這份 BCG 策略簡報，產出「簡報閱讀邏輯」文件（Word），供內部業務人員提案前閱讀。

品牌：{品牌名稱}
產品：{產品名稱}
通路：{通路範圍}
日期：{簡報日期}
```

**範例：**
> 請根據這份 BCG 策略簡報，產出「簡報閱讀邏輯」文件。
> 品牌：威德，產品：睡眠益生菌，通路：好市多 x momo，日期：2026.03

**必填欄位：**
| 欄位 | 說明 | 範例 |
|------|------|------|
| 品牌名稱 | 客戶品牌 | `威德`、`美強生` |
| 產品名稱 | 品類或產品線 | `睡眠益生菌`、`嬰幼兒奶粉` |
| 通路範圍 | 簡報涵蓋的通路 | `好市多 x momo`、`藥局婦嬰 x 電商` |
| 簡報日期 | 提案日期 | `2026.03` |

---

## 目的

將一份 InvosData 行銷策略簡報（三頁結構：封面 -> BCG 框架說明 -> Dashboard 整合頁）
轉化為一份供業務人員使用的「報告者參考手冊」——說明每頁的核心訊息、銜接話術、
常見客戶問題與回應建議。

這份文件讓業務人員在提案前有所依據，不需要每次從頭整理怎麼「說」這份報告。

---

## 工作流程

### Step 1：解析簡報內容

用 Python 提取 PPTX 全文，辨識以下結構：

```
P.1 封面     -> 品牌名稱、產品名稱、通路範圍、日期
P.2 BCG說明  -> STAR 與 Question Mark 各自的說明文字與適用維度清單
P.3 Dashboard -> 5 個欄位（客群名稱、BCG標籤、關鍵指標、當前瓶頸、核心機會、行動建議、InvosData 方案）
```

如果頁面結構不同（例如少於三頁、沒有 BCG 說明頁），仍按照現有頁面盡可能對應到六章架構，
並在文件中說明結構差異。

解析重點：
- 抓出每個 Dashboard 欄位的**欄名**、**BCG 標籤（STAR / Question Mark）**、**關鍵指標**
- 從「當前瓶頸」中找出最具衝擊力的 1-2 個論點（通常是反直覺的數字或缺失的機制）
- 從「核心機會」中找出最有說服力的比較數字
- 從「行動建議」中找出最具體的低成本可執行建議（例如貨架說明牌、QR Code、組合包）
- 從「invosData 方案」中對應每個欄位到 Insight / Media / API 三個產品線

### Step 2：準備文件資料

將解析結果整理為以下結構（對應 JS 腳本的資料區）：

```
BRAND = 品牌名稱（例：威德）
PRODUCT = 產品名稱（例：睡眠益生菌）
CHANNELS = 通路範圍（例：好市多 x momo）
DATE = 簡報日期
COLS = [5 個欄位的完整資料]
APPENDIX_DATA = 附錄數據（從 Dashboard 欄位標題與報告中萃取）
```

### Step 3：執行 JS 腳本產出文件

讀取本 skill 目錄下的 `references/generate_guide.js`，將 Step 2 整理的資料填入腳本的
**「填入新簡報資料」** 區段，然後執行：

```bash
# 在 repo 根目錄安裝依賴
npm install

# 執行生成
node skills/reading-guide/references/generate_guide.js
```

### Step 4：驗證輸出

確認輸出文件包含以下六章：
1. 文件用途
2. 整體敘事架構（含頁碼 x 核心任務表格）
3. 逐頁閱讀邏輯（P.1、P.2、P.3 各段，P.3 逐欄說明）
4. InvosData 解決方案說明邏輯（三產品線對應話術）
5. 常見客戶問答（至少 4 題）
6. 建議結尾話術 + 附錄數據速查表

## 六章文件架構（輸出規格）

### 一、文件用途
說明這份手冊的用途（供 InvosData 業務人員提案前使用）及所對應的簡報。

### 二、整體敘事架構
說明三頁簡報的敘事邏輯（診斷 -> 框架 -> 行動），並用表格呈現各頁核心任務。
結尾說明三頁之間的銜接邏輯（3 個 bullet）。

### 三、逐頁閱讀邏輯
#### P.1 封面
- 頁面目標
- 說話重點（2-3 個 bullet）
- 建議開場話術（callout box）

#### P.2 策略定位說明
- 頁面目標
- 兩個標籤（STAR / Question Mark）的解釋重點表格
- 常見卡點（2 個 bullet）
- Tip：P.2 通常不超過 3 分鐘

#### P.3 Dashboard（核心頁）
- 頁面目標
- 閱讀順序：方式 A（問題導向）與方式 B（輕重緩急）各為一個 callout box
- 各欄閱讀要點：逐欄說明，每欄包含：
  - 欄名 + BCG 標籤（標題行顏色：STAR 用藍色、Question Mark 用橘色）
  - 核心衝突或最有力論點（1 句話）
  - 最有衝擊力的數字或類比（1 bullet）
  - InvosData 切入點（1 bullet）

### 四、InvosData 解決方案說明邏輯
- 引導句
- 三產品線（Insight / Media / API）x 痛點話術表格
- 升級路徑建議（callout box）

### 五、常見客戶問答
- 表格：問題 x 建議回應方向（至少 4 題，從 Dashboard 瓶頸中萃取最可能被質疑的地方）

### 六、建議結尾話術 + 附錄
- 結尾話術（callout box）
- 附錄：關鍵數據速查表（從 Dashboard 萃取，含數字與對比品牌）

## 話術生成原則

生成各頁說話重點與常見問答時，請遵循這些原則，讓話術真正有用：

**最有力論點的格式**：「[直覺認知] 但其實 [反直覺數字/現象]」
例：「威德份額第一——但 95% 集中在一個通路，新競品進場就是結構性風險」

**InvosData 切入點的格式**：說清楚「沒有這個工具，會發生什麼事」
例：「沒有 invos API，好市多每賣一盒等於流失一個客戶的聯繫方式」

**常見問答生成邏輯**：
- 從瓶頸欄找「客戶最容易防衛性反駁」的點
- 從機會欄找「聽起來太樂觀、客戶會懷疑數字來源」的點
- 每個問答的回應要給「承認客戶說得有道理，但引導到更深的洞察」的結構

## 注意事項

- 中文繁體，字型 Microsoft JhengHei
- 不要直接把 Dashboard 的 bullet 原文貼進文件——要改寫成「說話的語氣」，即業務講給客戶聽的方式
- 數字要精確，直接從 PPTX 提取，不要自行估算
- 若 PPTX 有 5 個以上的欄位，選最重要的 5 個；若少於 5 個，照實際欄位數生成
- 如果有附件數據頁（例如熱銷 TOP10、成份趨勢），也可以加入附錄速查表
