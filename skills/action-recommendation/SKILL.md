# invosData 一頁式行動建議 Skill

> 🆕 **迭代狀態：第三代 BCG skill（最新版、推薦主力）。**
> 取代舊版 `bcg-analysis`（第一代）與 `bcg-channel-people`（第二代），但兩個舊版仍保留可用於需要完整四頁簡報的場景。
> **預設獨立使用即可**，skill 內建會依報告原檔切 5 欄客群/通路；若已跑過舊版 bcg 系列，欄位切法沿用不要重切。

> ⚠️ **排版硬性規則（所有 PPTX skill 通用）：所有標題列一律限縮在一行內。**
> 包含 header 卡的 title/subtitle/problem/goal，以及關鍵資訊/行動建議卡的粗體 head 小標。
> 欄寬 2.54"、fontSize 8 時，中文字 ≤ 15 字、英文+數字混合 ≤ 20 字為安全線。超過就**簡化用字**，
> 不要縮字型、不要加大卡片、不要改行距硬塞。產檔後務必開啟 PPTX 目視檢查，確認沒有任何一列折行。

## 與 bcg 系列的差異

| 維度 | bcg-analysis / bcg-channel-people（4 頁） | action-recommendation（本 skill，2 頁）|
|------|----------------------------------------|-----------------------------------|
| **目的** | 完整闡述市場觀點 + 四象限 + 瓶頸/機會/行動 | **濃縮成單頁**，直接給客戶看要做什麼 |
| **使用時機** | 提案首輪、高階會議、工作坊 | 提案收斂、第二次會議、客戶內部分享 |
| **核心訊息** | 為什麼這樣看市場 | **針對性關鍵資訊 × 對標目標 × invosData 可做的事** |
| **結構** | 4 頁：封面 / BCG 矩陣 / 瓶頸×機會 / 行動×方案 | 2 頁：封面 / 單頁整合（5 欄 × 3 列） |
| **讀者行動** | 建立共識 | 做決定 / 買單 |

**使用建議：** 本 skill 為**第三代、最新版、推薦主力**。**預設獨立使用**，skill 會依報告原檔內建切 5 欄客群/通路。
若先跑過舊版 bcg-analysis（第一代）或 bcg-channel-people（第二代）產出完整四頁簡報，**欄位定義（5 欄客群/通路）應沿用 bcg 的切法**，不要重新切，避免客戶看到兩份不一致。

## 你的任務

使用者已有市場數據報告（或已跑過 bcg 系列），要求你產出**一頁式行動建議 PPTX**。

**核心三大要素（這 skill 的命脈，每欄都要齊）：**

1. **突破性與針對性的關鍵資訊** — 不是通論，是這個品牌在這個客群/通路**獨有**的數據洞察
   - 壞例：「momo 是最大通路」（任何品牌都成立）
   - 好例：「momo 舊客 RPC $3,243 貼近通路均值 $3,253，產品沒問題、只是沒人提醒他再買」（針對性）

2. **對標整體市場或通路的關鍵目標** — 目標必須有 benchmark，不是憑空設數字
   - 壞例：「提升留存率」（沒對標、無法衡量）
   - 好例：「目標留存率 36%（對標通路均值）、PRC 對標通路均值 $3,253」

3. **針對關鍵目標的 invosData 行動建議** — 每條都必須是 invosData 做得到的事
   - 壞例：「加強品牌曝光」（空話、非 invosData 能交付）
   - 好例：「圈選 69% momo 品類流失買者投放廣告，推送品類需求內容重建使用習慣」（可執行、可歸因）

**固定輸出：3 頁深色主題 PPTX**
- Slide 1：封面頁（同既有 skills 的封面樣式，「行動建議」大字）
- Slide 2：**一頁式整合頁**，版面如下
  ```
  [頂部 title bar：品牌｜通路客群行動建議｜當前瓶頸 x 核心機會 x invosData 數據解決方案]
  ┌──────┬──────┬──────┬──────┬──────┐
  │ Col1 │ Col2 │ Col3 │ Col4 │ Col5 │  ← Header 卡：動詞+主題 / 副標 / 目標（對標）
  ├──────┴──────┴──────┴──────┴──────┤
  │           關鍵資訊（label bar）          │
  ├──────┬──────┬──────┬──────┬──────┤
  │      │      │      │      │      │  ← 突破性關鍵資訊卡（粗體小標+說明）
  ├──────┴──────┴──────┴──────┴──────┤
  │           行動建議（label bar）          │
  ├──────┬──────┬──────┬──────┬──────┤
  │      │      │      │      │      │  ← 行動建議卡（bullets + 目標數字）
  │ [t][t]│ [t][t]│ [t]  │ [t][t]│ [t][t]│  ← 底部 tag（類別標籤）
  └──────┴──────┴──────┴──────┴──────┘
  ```
- Slide 3：**附數據來源版**（與 Slide 2 內容 100% 相同，每段 problem/goal/insight/action body 末尾加上 `(P##)` 頁碼或 `【策略推論】`／`【invos 服務】`／`【策略方向】` 標籤，淡灰色 fontSize 7 不干擾主讀）。這是 Repo 級硬性規則的落地機制：每個數據與推論可逐一追溯原始頁碼，防止客戶追問「這個數字從哪來？」時答不出。

## Step 1：讀取報告（或 bcg 簡報）並擷取資料

```bash
python3 -c "
import zipfile, re
path = '<uploaded_pptx_path>'
with zipfile.ZipFile(path) as z:
    slides = sorted([n for n in z.namelist() if re.match(r'ppt/slides/slide\d+\.xml', n)])
    for i, s in enumerate(slides, 1):
        xml = z.read(s).decode('utf-8', errors='ignore')
        text = re.sub(r'<[^>]+>', ' ', xml)
        text = re.sub(r'\s+', ' ', text).strip()
        print(f'=== P{i} ==='); print(text[:1200]); print()
"
```

**擷取重點（每欄各需一套）：**

| 資料類型 | 用途 |
|---------|------|
| 該客群/通路的規模數據（人數、銷額、份額、YoY） | 寫進 header 目標卡當底氣 |
| 該客群/通路的核心痛點數據 | 寫進「關鍵資訊」卡 |
| 市場均值／通路均值／競品均值 | **對標目標的分母**（PRC、留存率、舊客佔比等） |
| 該客群可圈選的受眾條件（發票行為、跨品牌、購買頻率等） | 寫進行動建議，變成 invosData 可執行的動作 |

## Step 3：每欄填入三個要素

### 3.1 Header 目標卡（頂部彩色塊）

```
[動詞] [通路/客群名]
[副標：一句話講清當前瓶頸或定位]
──────────────
目標｜[指標1] [數字]、[指標2] 對標[市場/通路]均值 [數字]
```

**目標句的格式強制：** 每個數字必須有「對標什麼」—「留存率 36%」→「留存率 36%（對標通路均值）」。
若報告沒給 benchmark，**寧可不寫數字，寫定性方向**（「對標通路均值」「貼近市場水平」），不要憑空掰數字。

### 3.2 關鍵資訊卡（中段彩色塊）

每欄 **1-2 個子標題 + 說明段**，說明段需包含：
- **具體數字 + 對照**（「MD醫之方舊客 RPC 是新客 2.04 倍，整體市場只有 1.86 倍」）
- **why 推論**（「代表舊客忠誠度不差、願意花得更多」）
- **so what**（「每提升 1% 留存率的效益遠大於等量新客投入」）

**寫法規則：** 每段結尾要能回答「所以這對客戶意味著什麼？」不能只列數字。

### 3.3 行動建議卡（底部彩色塊）

每欄 **2-4 條 bullet**，每條用「動詞：做法，目標 [對標數字]」格式：

```
品類喚醒：圈選 69% 「momo MD醫之方」品類流失買者投放廣告，推送品類需求內容（非折扣），重建使用習慣後再推產品，目標留存率 36%
```

每條 bullet 要對應「關鍵資訊」裡的某個 why/so what，**不能是獨立 idea**。

### 3.4 底部 Tag（類別標籤）

每欄 **1-2 個 tag**，從固定字彙挑：
- `精準受眾`（媒體受眾圈選）
- `會員留存`（舊客留存機制）
- `新客導流`（新客入口與橋接）
- `發票回饋`（發票驅動活動）
- `LTV深化`（客單提升）
- `通路監測`（通路量化追蹤）
- `競品轉換`（競品客截獲）

Tag 用黑底白字，放在行動建議卡底部。

## Step 3.5：建立 SOURCES 對照表（Slide 3 必備）

與 COLUMNS 一對一定義每段內容的來源頁。AI 在撰寫 COLUMNS 當下就要同步填 SOURCES，不可事後補填（事後補填容易忘、錯配、或掰出推論當數據）。

```js
const SOURCES = [
  { // Col 1
    problem: "P##",                    // 原始報告頁碼
    goal: "P##, P##",                  // 多頁用逗號分隔
    insights: [
      { body: "P##" },                 // 純數據段落
      { body: "P##, 末句策略推論" },   // 數據 + 推論的混合段落
    ],
    actions: [
      { body: "【invos 服務】" },       // invos 產品能力，非原始數據
      { body: "P## + 策略推論" },       // 以某頁數據為基礎的推論
      { body: "【策略推論】" },         // 完全沒有原始數據支持的推論
    ],
  },
  // ... Col 2-5
];
```

**來源標籤規則：**
| 標籤 | 意義 | 何時使用 |
|------|------|---------|
| `P##` | 原始報告頁碼 | 內容來自原始報告的數據／描述 |
| `P##, P##` | 多頁組合 | 內容綜合自多頁數據 |
| `P## + 策略推論` | 數據 + 推論 | 以 P## 為基礎做的行動推論 |
| `P##, 末句策略推論` | 數據 + 結尾推論 | 前段是數據、結尾是推論 |
| `【策略推論】` | 純推論 | 完全沒有原始數據支持 |
| `【invos 服務】` | 產品能力 | 引用 invos Insight/Media/API 產品能力 |
| `【策略方向】` | 動作方向語言 | goal 只寫方向（「對標通路均值」）不寫數字時 |

**硬性規則（Repo 級）：** 若某段是【策略推論】或【invos 服務】（非原始數據），必須在寫進 COLUMNS 之前就主動向使用者標示「這段是推論、邏輯為何、請確認」，確認後才寫進檔案。詳見 Repo README 的「推論內容硬性規則」。

## 常見錯誤

| 錯誤 | 修正 |
|------|------|
| 目標數字沒寫 benchmark | 加「對標通路均值」「對標市場水平」或不寫數字 |
| 行動建議是通論（「加強曝光」） | 改成可圈選受眾的具體動作（「圈選 X 客群投放 Y 內容」） |
| 關鍵資訊只列數字沒 so what | 每段結尾加推論：「代表…」「意味著…」「所以…」 |
| 5 欄切法跟 bcg 不同 | 沿用既有切法，避免客戶困惑 |
| 憑空掰 benchmark | 寧可只寫方向（「貼近市場水平」），不要編數字 |
| COLUMNS 與 SOURCES 數字錯配（群組 A 的數字寫到 B 欄） | 填 SOURCES 時一定要重新對照原始報告頁、不要憑記憶；每欄填完立刻交叉驗證 |
| 把推論當成有數據支持的樣子寫入 COLUMNS | 寫之前先在 SOURCES 標記【策略推論】；若該段含推論，必須先跟使用者確認邏輯再寫進檔案 |
| 漏產 Slide 3 | 產檔後檢查 slides 數 = 3；若只有 2 頁代表 SOURCES 沒填或 slideOnePagerWithSources() 沒被呼叫 |
