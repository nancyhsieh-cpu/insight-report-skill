# invosData 市場洞察分析報告 Skill

## 使用者輸入模板

使用此 Skill 時，請在對話中提供以下資訊並上傳報告 PPTX：

```
此為 {報告期間} {品類}市場洞察分析報告

1. 請閱讀報告內容，收斂整體市場成長空間、通路分佈、品牌偏好、新舊客表現等現況
2. 針對品牌「{目標品牌}」提出具有針對性（針對{目標品牌}使用，當發現答案可以不看數據直接套用給其他品牌時就不具備針對性）與突破性（改變{目標品牌}認知）的市場洞察
3. 針對替「{目標品牌}」收斂出來的市場洞察，提出能扣回引客數據三大服務的數據與行銷方案策略建議。引客數據三大服務包含：invos Insight 市場機會洞察（賦能品牌智慧決策，建立可落地執行的策略）、invos Media 精準獲客轉換（高效鎖客，快速驗證，驅動全場景行銷擴散）、invos API（全通路會員整合，將單次消費顧客加入私域流量池，個人化經營）
```

**範例：**
> 此為 2025/12 MAT 益生菌市場洞察分析報告
> 1. 請閱讀報告內容，收斂整體市場成長空間、通路分佈、品牌偏好、新舊客表現等現況
> 2. 針對品牌「台塑生醫MD醫之方」提出具有針對性與突破性的市場洞察
> 3. 針對替「台塑生醫MD醫之方」收斂出來的市場洞察，提出能扣回引客數據三大服務的數據與行銷方案策略建議...

**必填欄位：**
| 欄位 | 說明 | 範例 |
|------|------|------|
| 報告期間 | MAT 期間或月份 | `2025/12 MAT`、`2602MAT` |
| 品類 | 市場品類名稱 | `益生菌`、`嬰幼兒奶粉` |
| 目標品牌 | 要分析的單一品牌（買這份報告的客戶） | `台塑生醫MD醫之方`、`美強生` |

---

## 你的任務

使用者上傳了一份市場數據報告，要求你針對指定品牌產出一份 Word 格式的「invos 市場洞察分析報告」。

**核心原則：所有洞察必須具有「針對性」**
- 針對性 = 這個洞察只適用於目標品牌，不能不看數據就直接套用給其他品牌
- 如果一個結論換成任何品牌都成立，那就不夠具體，必須重寫

**固定輸出：四章 .docx 報告**
- 第一章：市場整體現況
- 第二章：品牌專屬市場洞察（5 則，每則含數據發現 / 市場洞察 / 突破方向）
- 第三章：invos 三大服務策略建議
- 第四章：策略重點一覽（彙總表格）

## Step 1：提取報告數據

用 Python 讀取上傳的 PPTX 全文：

```bash
python3 -c "
import zipfile, re
path = '<uploaded_pptx_path>'
with zipfile.ZipFile(path) as z:
    slides = sorted([n for n in z.namelist() if re.match(r'ppt/slides/slide\d+\.xml', n)])
    for i, s in enumerate(slides, 1):
        xml = z.read(s).decode('utf-8', errors='ignore')
        text = re.sub(r'<[^>]+>', ' ', xml)
        text = re.sub(r'\s+', ' ', text).strip()
        print(f'=== P{i} ===')
        print(text[:1500])
        print()
"
```

整理以下數據（記錄頁碼備用）：

| 類別 | 要找的指標 |
|------|-----------|
| **市場規模** | 整體銷售額 YoY、購買人數 YoY、人均購買次數、單次金額 |
| **通路** | 各通路（藥局/電商/婦嬰）銷售佔比、人流佔比、YoY 變化 |
| **品牌競爭** | 目標品牌 vs 主競品的銷售額 YoY、市佔率變化 |
| **各階/各品項** | 各子品項的銷售佔比、人流 YoY、銷售額 YoY |
| **新舊客** | 新客人流 YoY、舊客人流 YoY、新舊客銷售佔比 |
| **目標品牌細節** | 各 SKU 的買家數、銷售額、購買次數、單次金、通路分佈 |
| **競品細節** | 主要競品的通路佔比、增長特徵、客群行為 |
| **跨品類** | 買者的其他購買品類（併買排行分析等）|

## Step 2：分析架構（四章內容）

### 第一章：整體市場現況

依序撰寫以下 5 個小節：

**1.1 市場成長結構**
- 核心問題：成長是靠「人變多」還是「買更多次」？
- 必含表格：整體銷售額 / 購買人數 / 人均次數 / 單次金，含 YoY
- 重點敘事：點明成長驅動結構（新客萎縮 vs 舊客深化的比值）

**1.2 各品項表現**
- 哪個品項是成長引擎？哪個品項受結構性衝擊？
- 必含表格：各品項銷售市佔 / 人流滲透 / YoY

**1.3 通路分佈與競爭格局**
- 各通路的份額移動趨勢
- 若有非授權通路問題，需特別說明

**1.4 品牌競爭態勢**
- 市場中各層級競爭格局
- 點名快速成長的競品及其增長驅動因素

**1.5 新舊客買者狀態**
- 新客 vs 舊客人流對比，說明結構性趨勢
- 結論：品牌成長重點應往「深化 LTV」還是「擴大人流」

---

### 第二章：品牌專屬市場洞察

**洞察品質標準（最重要的判斷依據）：**

> 當你寫完一則洞察，問自己：「這個洞察如果換成其他品牌，還適用嗎？」
> 如果適用，就不夠具針對性，必須重寫。
> 洞察必須根植於目標品牌的獨特數據表現，其他品牌看不到相同現象。

**撰寫 5 則洞察，每則格式固定：**

```
洞察標題：用有張力的「比喻型命名」，如「陷阱型成長」「商品化漂移」「升級斷層」
▶ 數據發現：具體數字 + 與市場均值 / 競品的對比，說明「異常」在哪裡
▶ 市場洞察：解釋這個異常背後的消費者行為邏輯或結構性原因
▶ 突破方向：改變品牌現有認知的行動路徑，要有具體落地感
```

**洞察發掘方向（從以下角度找「只屬於這個品牌」的數字異常）：**
- 銷售額成長 vs 市佔率 / 購買人數的背離
- 單次金額異常（過低 / 過高 / 快速下滑）
- 某通路佔比極端集中（>80% 在單一通路）
- 新客流失速度超過市場自然衰退速度
- 某 SKU 的舊客增長爆發但新客同步萎縮（黏性信號）
- 品項升級流失：消費者有沒有跟著品牌走？
- 通路空白：主競品都在做、這個品牌卻缺席的通路
- 非授權通路滲透：是否有定價秩序問題？
- 跨品類購買信號：買者還買什麼？

---

### 第三章：invos 三大服務策略建議

每個服務對應 3-4 個具體方案，每個方案格式：
**◆ 方案名稱**（一行）+ 執行內容（3-5 句，約 80-120 字，有具體數字）

**invos Insight｜市場機會洞察**
- 服務定義：賦能品牌智慧決策，建立可落地執行的策略
- 適合對應：品牌健康指數監測、競品崛起解碼、升級轉換率分析、通路結構報告
- 每個方案要說明「追蹤什麼指標」「多久提供一次」「協助品牌做什麼決策」

**invos Media｜精準獲客轉換**
- 服務定義：高效鎖客，快速驗證，驅動全場景行銷擴散
- 適合對應：精準受眾圈選（依發票行為）、廣告投放時機、轉換漏斗優化
- 每個方案要說明「圈選哪個受眾」「在什麼時機 / 什麼平台投放」「預期什麼效果」

**invos API｜全通路會員整合**
- 服務定義：將單次消費顧客加入私域流量池，個人化經營
- 適合對應：跨通路資料整合、升級旅程自動化推播、訂閱制 / 補貨提醒、非授權通路識別
- 每個方案要說明「整合哪些數據來源」「觸發什麼動作」「帶來什麼留存效果」

---

### 第四章：策略重點一覽

三行彙總表，對應三大服務 x 各 3 條核心行動（含洞察編號）：

```
invos Insight | ① 方案名（洞察#X）  ② 方案名（洞察#X）  ③ 方案名（洞察#X）
invos Media   | ① ...
invos API     | ① ...
```

## Step 3：生成 Word 文件

讀取本 skill 目錄下的 `references/docx-template.js` 作為程式碼起點，用 Node.js + docx 套件生成 .docx。

```bash
# 在 repo 根目錄安裝依賴
npm install

# 複製 template 並修改品牌資料後執行
node skills/insight-report-summary/references/docx-template.js
```

**文件設計規範：**

| 項目 | 規格 |
|------|------|
| 頁面尺寸 | A4（11906 x 16838 DXA）|
| 邊距 | 上下左右各 1440 DXA（2.54cm）|
| 預設字體 | Arial |
| 標題色 | `2E75B6`（深藍）|
| 封面副標 | `品牌名稱 品牌專屬市場洞察與 invos 服務策略建議` |
| 洞察框 | 每則洞察用淺灰底表格包裹（fill: `F0F4F8`）|
| 服務建議表格 | 左欄：服務名稱（深色底，白字）；右欄：方案內容 |
| 彙總表格 | 三行，標題欄用各服務色（Insight 綠 `16A34A`、Media 青 `0891B2`、API 紫 `7C3AED`）|
| 數據表格 | 灰色邊框（`CCCCCC`），表頭淺藍底（`D5E8F0`）|
| 輸出路徑 | repo 根目錄下 `output/insight-report-summary/<品牌>市場洞察分析報告_invos.docx` |

## Step 4：驗證輸出

```bash
# 確認文件可以用 pandoc 讀出標題結構
pandoc <output_path>.docx -t markdown 2>/dev/null | grep "^#" | head -20
```

確認：
- [ ] 四章標題都存在
- [ ] 5 則洞察各有「數據發現 / 市場洞察 / 突破方向」
- [ ] 三大服務各有 3-4 個方案
- [ ] 所有數字有具體來源（不是空泛描述）
- [ ] 每則洞察能通過「換品牌還適用？」的針對性測試
